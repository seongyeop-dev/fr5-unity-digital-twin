# 06. 프로젝트 범위

## 주요 문제와 해결

| 문제 | 원인 | 해결 방법 | 결과 |
|:---|:---|:---|:---|
| 메뉴마다 방문해야 하는 작업 위치가 다름 | 메뉴 1과 메뉴 2가 서로 다른 펌프 위치 사용 | DI 0·DI 1 입력을 구분하고 위치 1~3·4~6으로 분기 | 메뉴별 제조 시연 완료 |
| 주요 이동과 작업 위치 접근의 역할이 다름 | 장거리 이동과 수직 접근을 같은 방식으로 처리하기 어려움 | 주요 이동은 PTP, 작업 위치 접근·이탈은 LIN으로 구분 | 작업 순서를 모션별로 분리 |
| 컵·뚜껑 작업에서 파지·해제 시점 관리 필요 | 단계마다 그리퍼 개방 값과 위치가 다름 | 각 작업 포인트에서 `MoveGripper`를 명시적으로 실행 | Pick & Place와 컵·뚜껑 작업 완료 |
| 제조 후 다음 작업의 기준 위치가 필요 | 프로그램이 반복 입력을 대기하는 구조 | 작업 종료 시 Home 복귀 | 다음 입력을 위한 초기 상태 확보 |
| 개인 작업과 팀 통합 결과 구분 필요 | Pick & Place와 전체 칵테일 제조의 구현 범위가 다름 | 개인 Lua·포인트와 팀 통합 Lua·영상 근거를 분리 | 기여 범위를 과장 없이 문서화 |

## 최종 구현 범위

- 실제 FR5 Pick & Place
- DI 0·DI 1 메뉴 분기
- 메뉴별 펌프 위치 3개 순차 방문
- PTP·LIN·MoveGripper·WaitMs·Spiral 실행
- 컵·뚜껑 작업과 완성 컵 배치
- 작업 완료 후 Home 복귀
- Lua 2개, 포인트 DB, 영상 3개와 이미지 6개 공개

## 범위 제외

이 저장소는 중간 시연 데모의 완료 결과만 다룹니다. 비전 인식, 주문 앱, 레시피 서버, Python FK, Unity Digital Twin, ROS2·Gazebo·MoveIt과 SDK 실시간 연동은 포함하지 않습니다.

산업용 안전 인증, 설비 인터록, 정량 반복 성공률과 사이클타임 측정도 이 시연 범위에는 포함되지 않습니다.
